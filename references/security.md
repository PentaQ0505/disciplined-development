# Secrets, privacy, and external operations

Use for credentials, personal data, external APIs, online consoles, purchases, and store submissions.

- Never place secrets in source, Git, logs, screenshots, store materials, temporary documents, or chat. Do not copy private keys to third-party services for convenience.
- Before an external API call, verify the project, account, application identifier, environment, and read/write scope. Treat other projects' scripts as read-only references unless separately authorized.
- Report only privacy and compliance claims supported by code, configuration, or direct verification. For example, absence of a discovered upload does not prove the product has no network code.
- Do not treat technical QA as platform approval or guarantee a review outcome.
- Uploading, publishing, submitting for review, changing live store/console data, purchases, and sending data externally require explicit authorization for the target and action. Skill guidance does not grant that authorization.

The source document contains App Store Connect credential instructions for a specific app. Those exact app identifiers and account-specific constraints belong in that project's private instructions, not in this general skill.
